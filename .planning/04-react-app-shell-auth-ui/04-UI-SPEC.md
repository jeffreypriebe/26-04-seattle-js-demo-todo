## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline label padding |
| sm | 8px | Input field inner padding (vertical), icon-to-label spacing in nav |
| md | 16px | Default element spacing, form field gaps, card padding |
| lg | 24px | Section padding, auth card padding |
| xl | 32px | Layout vertical rhythm between form groups |
| 2xl | 48px | Auth screen top offset (center card vertically on mobile) |
| 3xl | 64px | Reserved for future phase-level layout gaps |

Exceptions:
- Bottom navigation bar height: 56px (not a standard scale step — required to meet 44px touch target with visible label text below the icon)
- All interactive elements (nav items, buttons, form controls): minimum 44px height/width touch target — enforced via Tailwind `min-h-[44px]` or Radix primitive defaults (source: UX-03)

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — white in light mode | Page background, auth screen background |
| Secondary (30%) | `hsl(var(--card))` — near-white / light gray | Auth form card surface, bottom nav bar background |
| Accent (10%) | `hsl(var(--primary))` — shadcn default blue | Specific elements listed below |
| Destructive | `hsl(var(--destructive))` — shadcn default red | Destructive actions only — none in Phase 4 |

Accent reserved for:
1. Primary CTA button fill ("Sign in", "Create account") — text on accent is white
2. Active bottom navigation item (icon + label color only, not background fill)
3. Form field focus ring

Accent is NOT applied to: inactive nav items, input backgrounds, card surfaces, helper text, headings, or any decorative element.

**Color tokens:** Use shadcn CSS variable names (`--background`, `--card`, `--primary`, `--destructive`, etc.) — do not hardcode hex values. This ensures light/dark mode compatibility without extra work.

## Layout Contract

### App Shell

The root layout fills the full mobile viewport without overflow:

```
height: 100dvh  (dynamic viewport height — adjusts when virtual keyboard appears)
fallback: 100vh (for iOS Safari < 15.4 — see dvh note below)
```

**dvh browser support note (from STATE.md blocker):** `dvh` is supported in iOS Safari 15.4+ (released March 2022). As of 2026, Safari 15.4+ represents >97% of active iOS users. Use `dvh` as the primary value with `vh` as a CSS fallback via the cascade:

```css
height: 100vh;        /* fallback for very old iOS Safari */
height: 100dvh;       /* overrides for browsers that support it */
```

In Tailwind v4, use: `h-[100dvh]` with a custom fallback class or the `@supports` directive in `app.css`.

### Layout regions

```
┌─────────────────────┐
│   Content area      │  flex-1, overflow-y-auto, pb-[56px]
│   (auth OR tabs)    │
├─────────────────────┤
│  Bottom Nav (56px)  │  fixed, bottom-0, left-0, right-0, z-50
└─────────────────────┘
```

- Content area: `flex-1 overflow-y-auto` — scrolls independently of nav
- Bottom nav: `fixed bottom-0 left-0 right-0 h-[56px] z-50` — always visible above keyboard (keyboard pushes content area, not nav)
- Safe area insets: apply `pb-safe` or `padding-bottom: env(safe-area-inset-bottom)` to bottom nav for devices with home indicators (iPhone X+)

### Virtual keyboard handling

When the virtual keyboard opens on mobile:
- `dvh` causes the content area to shrink to the visible area
- The bottom nav stays fixed and remains visible
- Focused form inputs scroll into view automatically via `overflow-y-auto` on the content area
- Do NOT use `position: fixed` on any element inside the content scroll area

### Auth screens

- Auth card: centered in content area, max-width 400px, full-width on narrow viewports
- On narrow mobile (< 400px), auth card is full-bleed with `md` padding on sides
- Input fields: full width within the card, `min-h-[44px]`
- No modal or drawer for auth — full-screen route (`/login`, `/signup`)

### Bottom navigation

- Two tabs: "Personal" and "Team"
- Each tab: icon (24px lucide icon) stacked above label text (12px, Label role)
- Active tab: accent color for icon + label
- Inactive tab: muted foreground (`hsl(var(--muted-foreground))`)
- Tab touch target: full width of the tab column, min-height 56px (the nav bar height)
- No badge or notification count in Phase 4

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Tab switch (bottom nav) | Instant — no animation, no loading state. React Router navigation only. |
| Form submit (sign in / create account) | Button enters loading state ("Signing in...") immediately on tap. Disabled during request. Error message appears inline below form on failure. Success navigates to home. |
| Password field | Masked by default. No show/hide toggle in Phase 4 (deferred). |
| Form validation | Validate on submit only (not on every keystroke). Show one error per field. |
| Keyboard dismissal | Tapping outside input on mobile dismisses keyboard — browser default, no custom handling needed. |
| Auth link navigation | Login ↔ Signup links are anchor tags / `<Link>` components — full route navigation, not modal swap. |
